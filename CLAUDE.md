# CLAUDE.md

## What this repo is
Reproduction package + AASTeX manuscript for a paper submitted to ApJ:
**"Combining the Mass–Radius Posteriors of PSR J0030+0451 Allowing for Unknown Model Systematics"**
Authors: Ryan O'Connor (`\ROC`, undergrad, Metzger Family Foundation fellowship), Chun Huang (`chun.h@wustl.edu`, corresponding author), Alexander Y. Chen (`\AC`) — WashU Physics.

The paper combines 8 published mass–radius (M–R) posteriors of PSR J0030+0451 from NICER pulse-profile modeling (PPM) into one Bayesian "combined" posterior, using a Press (1996) good/bad mixture model with a KDE-based good component. **The paper was reviewed by ApJ and the referee recommended rejection** (see `feedback.md`). We are now working through a revision. This file orients a fresh session on the repo layout, the method, and exactly what the referee objected to, so we don't have to re-derive it each session.

- `figures/` — output PNGs referenced by the manuscript (`KDECompactness.png`, `3x3Posterior.png`, `MarginalPosteriors.png`, etc.).
- `1D_Compactness_Combination.ipynb`, `2D_MassRadius_Combination.ipynb` — the notebooks that produce the **currently published** headline results (Figs. 1–4, Tables 1–2 as written in `manuscript.tex` now).
- `2D_MassRadius_WithClasses.ipynb` — exploratory variant: adds a `CLASS_MAP` that groups models sharing the same underlying dataset (e.g. Riley19 + all Vinciguerra24 configs + Kini26 → one class; Miller19 2spot/3spot → another), sums the "good" KDEs within a class before combining. First attempt at addressing non-independence; not wired into the manuscript numbers.
- `tests/1D_correlation_tempered.ipynb`, `tests/2D_correlation_tempered.ipynb` — most recent (latest commit) exploratory notebooks, more developed than `WithClasses`. They define a `GROUPS` dict (`Riley`, `Miller`, `Vinciguerra`, `Kini`), pool posteriors within each publication-group, then marginalize over a correlation-tempering parameter `rho` (on a grid) meant to soften the effective independence between groups before the final combination. Still WIP: heavy inline diagnostics/prints, duplicated cells, not reproducing manuscript figures/tables yet, not referenced by `manuscript.tex`.
- `plotting.ipynb` — small utility to replot a chosen subset of models.
- `tests/independence_sensitivity.py`, `tests/independence_sensitivity_2d.py` — standalone scripts (only `.py` files in the repo; run with plain `python`, write to `tests/independence_sensitivity_figures/`). A third, distinct attempt at the independence problem, referred to in their own docstrings as "Option B": rather than fixing the method (grouping/pooling, as in `WithClasses`/`*_correlation_tempered.ipynb`, "Option A/C"), they reuse the **published good/bad pipeline completely unchanged** and ask how much the final posterior's position/width move if each measurement's mixture-likelihood term is raised to a power `w_i <= 1` (a standard power-likelihood/design-effect correction for pseudo-replication, `w = 1/(1+(n-1)*rho)` for `n` measurements sharing correlation `rho`). `w_i=1` for all reproduces the published result exactly (sanity-checked against `manuscript.tex` numbers). Four scenarios: `published` (rho=0), `global sweep` (all 8 as one group, rho swept 0→1), `grouped sweep` (the same 4 paper-groups as `*_correlation_tempered.ipynb`, each tempered independently), and `referee_informed` (one discrete scenario built from an explicit 8×8 correlation matrix using numbers read directly off `feedback.md`'s own claims — rho=1 within Riley19/Miller19, rho=1 within Vinciguerra24's 4 models, rho=0.98 Riley/Miller-vs-Vinciguerra from the referee's "98% shared photons," rho=1/1.5 Kini26-vs-rest from the manuscript's "~50% more NICER counts" line). The 1D script targets compactness `C`; the 2D script is the same idea applied to the full `2D_MassRadius_Combination.ipynb` pipeline, targeting the headline `M`, `R` numbers directly. **The docstrings flag the `0.98`/`1/1.5` correlation numbers as the author's own back-of-envelope reading of the referee's text, not measured photon counts — explicitly asked to be checked/replaced before use in a response letter.**
- No `.ipynb`-adjacent Python modules beyond the two scripts above; no `requirements.txt`/`environment.yml` — everything else lives in notebooks. Imports used throughout: `numpy`, `matplotlib`, `scipy.stats` (`gaussian_kde`, `norm`, `multivariate_normal`), `scipy.ndimage`, `scipy.special.logsumexp`, `scipy.signal.fftconvolve`, `seaborn`.

## The method as currently published
- Press (1996) good/bad mixture: each measurement's likelihood is `p·P_good + (1-p)·P_bad`, marginalized over mixing probability `p` (flat prior) and per-measurement nuisance params.
- **Good component** `P_G,i`: replaced (this paper's extension over Press 1996) with a non-parametric KDE built from the published posterior samples (`scipy.stats.gaussian_kde`, multivariate Silverman bandwidth) instead of a Gaussian — needed because published PPM posteriors are skewed/multimodal.
- **Bad component** `P_B,i`: Gaussian centered on the good posterior's median `mu_i`, diagonal covariance `Sigma_S,i = diag(S_i,a^2)`, with baseline width `S_i,a` calibrated so the bad Gaussian's 68% CI covers ~99% of the good posterior (Eq. 8); further inflated by a width-scale `alpha_i` (prior `exp[-alpha_i]`, `alpha_i>=1`) and shifted by `Delta_i` (zero-mean Gaussian prior, hyperprior `1/sigma_Delta` on its width). Construction is inspired by Bernal & Peacock 2018, but shift/scale are applied only to the bad component here (Bernal & Peacock apply them to the full posterior).
- Applied to **8 inputs treated as independent**: Riley19 ST+PST; Vinciguerra24 ST+PST/ST+PDT/PDT-U/ST-U; Miller19 2spot/3spot; Kini26 PDT-U.
- Headline results: `C = 0.172^{+0.006}_{-0.007}`, `M = 1.46^{+0.09}_{-0.08} Msun`, `R = 12.69^{+0.64}_{-0.55} km`; per-measurement "credibility" `P_i` (Table 2) ranks Kini26 PDT-U highest (0.81), Vinciguerra24 ST+PST lowest (0.20).
- Downstream: combined with PSR J0437-4715 and GW170817 (EoS-agnostic, following Huang:2024wig / Huang:2025mrd) for `R_1.4 = 11.98^{+0.58}_{-0.68} km` and `Lambda_1.4 = 320^{+216}_{-138}`.

## Referee's core objection — the thing that has to be resolved to resubmit
**The independence assumption is invalid**, and the manuscript's own hedge language ("practically necessary approximation," §2.3/§3.3) does not fix it — the referee says this cannot be resolved by caveat, only by a methodology change. Concretely:
1. Riley19 ST+PST, Miller19 2spot, Miller19 3spot all use the **exact same dataset**.
2. Vinciguerra24's four models add only ~2% new XMM data on top of the same NICER data as Riley19/Miller19 (98% of photons shared); its ST+PST is the **literal same model** as Riley19's.
3. Kini26 PDT-U extends the same NICER data further and shares the same XMM data as Vinciguerra24; its solution is a mix of Vinciguerra24's ST+PDT and PDT-U.
- Net effect: most photons are counted ~8× over, producing an overconfident combined posterior (~2× too narrow), inconsistent with some inputs (e.g. Vinciguerra24 ST+PST lies almost entirely outside the combined 68% region), and an `R_1.4` uncertainty ~3× smaller than Huang2025a with no new data — the referee flags this as the smoking gun.
- Referee's suggested reframing: repurpose the framework to **estimate PPM systematic uncertainty** rather than to produce a sharper combined M–R posterior for direct EoS use — described as "a very different avenue" from the current paper, but one the referee sees value in.

### Secondary methodological criticisms
1. All input M–R posteriors given equal weight regardless of within-analysis Bayesian evidence (e.g. Vinciguerra24 say ST-U/ST+PST are "strongly disfavored" by evidence) — should be down-weighted, not ignored.
2. Bad-component covariance `Sigma_S,i` is diagonal (no M–R cross-correlation), but compactness `M/R` being the primary PPM observable implies a real M–R correlation even under systematics — likely should not be diagonal.
3. Overclaiming: "robust" / "conservative" language used without quantitative demonstration; needs a broad prior-sensitivity study or comparison to alternative frameworks.
4. Endorses investigating "quantifying systematic contributions" as a reframed contribution — this is what the class-splitting and correlation-tempering notebooks are reaching for.

### Reviewer's notebook questions (need answers/discussion, likely in the response letter)
- Lowering the `alpha` prior's lower bound to 0.1 (allowing overconfident "bad" distributions) barely changes the final posterior — why?
- Forcing `p → 1` (good-only) gives a posterior not much tighter than the reported one, suggesting the systematics term contributes little and the "good" KDEs alone drive the constraint.
- Small mismatch between the 1D compactness posterior (direct KDE combination on `C` samples) and the compactness derived from the combined 2D `(M,R)` posterior via `C=M/R` — the derived version down-weights the high-compactness tail.

## Open direction on the independence fix (as of 2026-09-10)
Ryan's tentative preference: rather than picking fixed/discrete correlation values for `rho`, **marginalize over `rho`** (integrate it out under a prior, the way `sigma`/`alpha`/`p` are already marginalized in the published method) so the final posterior stays agnostic about the true degree of model dependence. Ryan supplied `correlation_tempered_kde_pooling_framework.pdf` (repo root), a technical design doc formalizing exactly this: a tempering factor `kappa(rho) = 1/(1+(N-1)rho)` applied to the pooled log-likelihood (Eq. 5-6), `rho` marginalized against a prior (recommended: `Beta(4,1)` as "main conservative", `Uniform(0,1)` as a sensitivity check, plus `rho=0`/`rho=1` as diagnostic endpoints), plus a new group-level systematic covariance `Sigma_sys` applied via Gaussian convolution of the pooled posterior (Eq. 9), and (in 2D) a full non-diagonal bad-component covariance addressing the referee's secondary M-R-correlation criticism.

**First implementation**: `tests/correlation_tempered_pooling_1d.py` (1D compactness case only so far; 2D is the deliberate next step, not yet built). Key decisions made when implementing (confirmed with Ryan or forced by debugging):
- Mixing probability `p` kept **shared** across all 8 measurements (matches published method / `independence_sensitivity.py`), not per-measurement `p_i` as the PDF's Eq. 17-18 literally allows — Ryan's explicit choice, so that the `rho=0, sigma_sys=0` limit reproduces the published `C=0.172` result exactly and isolates `rho`/`sigma_sys` as the only new ingredients.
- `sigma`/`alpha`/`delta` (bad-component nuisance params) still marginalized via the published method's exact deterministic trapezoid quadrature (not Monte Carlo, despite the PDF's pseudocode) — shown to be mathematically equivalent to prior-predictive marginalization, and needed to reproduce the published grids bit-for-bit.
- **Do not pad `C_grid` beyond the raw data range for the `sigma_sys` convolution margin**, despite the PDF (Sec 4.1) recommending a margin. Tried it; it broke the `rho=0` sanity check (width 0.0093 vs. published 0.013) because it changes how the bad component's Gaussian tails get truncated/renormalized within-domain. Keep the grid identical to `independence_sensitivity.py`/the published notebook (raw range, 200 pts); accept that the `sigma_sys` convolution loses a little mass near domain edges as a known, acceptable limitation of this diagnostic script.
- Validated: `rho=0, sigma_sys=0` gives `C = 0.1716 +0.0061/-0.0066`, matching the manuscript's `0.172 +0.006/-0.007`. Diagnostic scenarios (rho=1, rho~Uniform, rho~Beta(4,1) w/ and w/o sigma_sys) all produced, plotted to `tests/correlation_tempered_pooling_figures/`. Widths relative to published: rho=1 -> 4.32x; rho~Uniform(0,1) -> 2.91x; rho~Beta(4,1) -> 3.93x; rho~Beta(4,1)+sigma_sys -> 4.09x.
- Not yet implemented: model-weight sensitivity (equal vs. within-analysis evidence weights, PDF Sec 7 item 5) — needs Bayesian evidence values per model, not present in `datafiles/`.
- **No single "main" rho prior chosen yet** — Ryan explicitly wants Beta(4,1) and Uniform(0,1) reported as co-equal diagnostics for now rather than picking a headline prior (2026-09-10); revisit once 2D numbers exist.
- **2D `(M,R)` extension paused at Ryan's request (2026-09-10)** — review the 1D results/figures first before building `tests/correlation_tempered_pooling_2d.py`. Don't start it unprompted.
- **Portability note**: `tests/correlation_tempered_pooling_1d.py` uses `np.trapz` (not `np.trapezoid`) throughout, deliberately — Ryan's machine has two Python installs, one with numpy <2.0 (`np.trapezoid` doesn't exist there, only added in numpy 2.0). `np.trapz` still works (with a harmless deprecation warning) on both, so don't "clean up" to `np.trapezoid` again without checking which interpreter actually runs it.

### Ensemble/agreement diagnostics added to `correlation_tempered_pooling_1d.py` (2026-09-11)
Two diagnostics added on top of the 1D scenarios, per Ryan's ask for posterior diagnostics on agreement/correlation across the ensemble (not built: pairwise empirical overlap matrix, per-model tension-vs-combined-posterior — Ryan didn't select those this round, still open options if wanted later):
- **Per-model credibility `P_i` across scenarios**: reimplements, in spirit, the manuscript's Table 2 `P_i` diagnostic (`2D_MassRadius_Combination.ipynb`, "Posterior values of P_i") but in 1D compactness space, for each of the 5 scenarios. Deliberately differs from the published notebook: (a) 1D not 2D, so it won't reproduce the manuscript's exact 0.20-0.81 numbers, only rough ordering; (b) omits that notebook's unexplained `1000 *` scaling factor (worth asking Chun Huang whether that was intentional or a bug) — this version is a properly normalized `[0,1]` probability. The per-model good/bad split itself always uses the untempered (`rho=0`) sigma-marginalized bad component regardless of scenario — only the combined posterior used to weight each model's credibility changes across scenarios. Result: ordering is preserved across all scenarios and roughly matches the manuscript's (Vinciguerra24 ST+PST lowest, Kini26 PDT-U highest), but tempering compresses/lowers credibility broadly (published range ~0.34-0.66 -> tempered range narrows and drops, e.g. ~0.25-0.53 under rho~Beta(4,1)+sigma_sys).
- **Data-implied rho (evidence vs. rho)**: computes `Z(rho)`, the marginal evidence at each tempering level (exposed from `combine_1d_given_kappa`'s internal sigma-evidence integral, `Z(rho) = integral over sigma of evidence_sigma(sigma)*prior_sigma(sigma)`), swept across `RHO_GRID` and plotted as `log[Z(rho)/Z(0)]`. **Important corrected finding** (the code originally guessed the opposite before being run and checked): `Z(rho)` is **monotonically decreasing** in rho — maximized at `rho=0`, not `rho=1`. Mechanism: the 8 good KDEs mostly peak in overlapping regions of C, so the untempered product (`kappa=1`) reinforces that overlap into a very sharp/large pointwise density there; tempering suppresses exactly that reinforcement. **This means a naive evidence-based choice of rho would always collapse back to rho=0 — i.e. to treating the 8 measurements as fully independent** — which is precisely the overconfident, pseudo-replication-prone assumption under dispute. Read as: naive evidence comparison is circular/invalid for picking rho here, not just impractical, which is a stronger and more useful point for the response letter than "evidence would trivially favor full pooling" (the reverse of what was first assumed). This is why rho is fixed via prior/design-effect reasoning (Beta(4,1)/Uniform) rather than fit to data — now with a concrete, checked justification rather than an assumption.
